# 象五子棋多端交互与好友房间

## 本轮规则

- 用户要求移除楚河汉界；可选择象棋 9×10 或五子棋 15×15 棋盘。
- 兵卒无方向、河界限制，横竖任意方向一步。象、士、将均不受区域限制；保留马腿、象眼和炮架。
- 切换棋盘在已有棋局时确认重开，不将已有棋子强行映射到新棋盘。
- 用户已确认双人邀请房间：红黑各一名玩家。

## 实现

1. `game.js` 统一使用当前棋盘列数计算移动、阻挡、边界与连线。`game.test.js` 覆盖两种尺寸与兵卒新走法。
2. `pieces.js` 提供七类半透明矢量形态、按棋种区分的移动轨迹、入场和吃子双方动画。动画期间锁定行动，尊重减少动态效果设置。
3. `app.js`、`index.html`、`style.css`：手机操作区在棋盘上方，隐藏顶部双棋池，大号重开按钮，悬浮手记弹窗，15×15 可放大横向浏览。桌面保留三栏。禁用页面 contextmenu，仍支持触摸和键盘。
4. `rooms.js` 在现有 Node 服务加入两人房间。服务端维护棋局并抽子；玩家令牌、棋局版本和回合检查防止越权/重复行动；每秒同步，重开需双方同意，支持取消。
5. 会话凭证只保存在当前标签页的 sessionStorage，邀请链接没有凭证。房间内棋盘类型固定，刷新可恢复席位；返回同屏会放弃席位。
6. `build.js` 输出仅含前端文件的 `dist/`，相对资源路径兼容 GitHub Pages 仓库子路径。

## 联机部署边界

- GitHub Pages 是静态托管，不能运行房间 API 或作为实时消息中转。前端可上 Pages，后端须运行 `node server.js`，或后续改用托管实时服务。
- 当前为单进程内存房间，最多 100 个；闲置 1 小时或建立 24 小时后过期，服务重启清空。扩展多实例或持久化时再引入共享存储。
- 同一来源运行无需额外设置。前后端分离时，设置后端 `FRONTEND_ORIGIN` 为前端精确来源（不含路径），页面填写 HTTPS 房间服务地址。
- 本轮只本地验证，没有发布到 GitHub 或公网，没有实际手机/跨运营商网络测试。

参考：[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)、[WebRTC 建连说明](https://webrtc.org/getting-started/peer-connections?hl=en)。

## 验证结果

- `npm test`：10 项测试通过，含真实 HTTP 鉴权、越权、过期版本、重复抽子、尺寸边界、双方重开、非法/超大请求及 CORS。
- 双浏览器页面创建/加入 15×15 房间，完成兵卒后退、刷新恢复、双方重开及九手五连；两端均为 5 枚高亮、225 个禁用位置，日志无 warning/error。
- 同屏实际验证部署时 1 个运动棋子、吃子时攻击者/受击者 2 个运动棋子与冲击圈，动画期间输入锁定；减少动态效果开启时无动画且及时解锁。
- 320、390、844、1280px 目标视口均无水平溢出；窄屏和手机横屏操作按钮在棋盘上方，重开触摸区域 44px。放大只滚动棋盘内部。
- 完整手记弹窗、棋盘切换取消保护、15×15 的 O15 边界部署、右键禁用均已操作检查。
- `npm run build` 成功；通过临时静态服务的 `/dist/` 子路径实际落子，缺少房间 API 时显示明确提示。临时静态服务验完关闭。
