# TapTap H5 长广告奖励与首次加载修复

> 历史中间版本，已由[打开成功后停表方案](../h5-ad-open-timeout-2026-10-19/README.md)替代。下文的 180／226 秒时限只记录当时实现，不应作为新接入规范。

排查始于 2026-10-18，验证完成于 2026-10-19。用户反馈首次唤起超过 10 秒、广告播放 15–60 秒，广告页显示任务完成，返回仍显示广告暂不可用／提示未成功生成。

## 已确认原因

共享 H5 广告适配器和游戏 `createHintAccess` 各有一个 45 秒总截止时间，均从请求开始计时，包含广告加载和播放。广告长于该限制时，完成回调到达前请求已失败并销毁实例。以前的可见性修复未覆盖此问题。

`before.txt` 保存修复前的三条失败回归：12 秒加载＋60 秒播放仍返回 failed、外层等待也提前失败、没有预加载入口。尚未取得用户设备真实 SDK 日志，不能断言所有 15 秒广告失败都由同一个原因造成。

## 修改

- TapTap H5 加载最多等待 45 秒；开始展示后单独等待最长 180 秒的完成／关闭回调，游戏层读取宿主总预算 226 秒，避免提前取消。其他渠道保留原有超时行为，原生适配器仍使用其已有明确预算。
- 首页提前调用 SDK load，点击消费同一个广告实例；不自动播放。加载中点击不重复加载，失败可重试，退出会释放。空闲导航不再误销毁已预加载实例。SDK 注入晚于首页、广告库存或网络慢仍可能导致首次等待。
- 等待按钮显示“准备广告…”，说明观看完成后分析／悔棋。提示仍先广告后分析，首免和广告悔棋规则不变。
- 仅 `onClose({isEnded:true})` 产生完成奖励，不根据停留时长、show Promise、页面恢复或任意真值发奖。隐藏时收到结果等前台恢复再交付；明确退出后忽略旧结果。
- 保存最近 40 条加载、展示、关闭、失败、超时阶段及可见性事件到 `localStorage['xiangqi-five-ad-diagnostics']`，版本 `h5-ad-timing-20261018`。既有开发面板的状态快照包含 `game.ads`；普通玩家界面不显示调试信息。事件不保存广告素材、账号、凭证或完整错误文本；存储不可用不影响奖励。

官方参考：[广告接入指南](https://developer.taptap.cn/minigameapidoc/quick-start/mcp-guide/ad-integration-guide/)、[onClose](https://developer.taptap.cn/minigameapidoc/dev/api/ad/RewardedVideoAd.onClose/)。
