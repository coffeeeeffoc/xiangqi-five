# 山间棋亭与对局体验

采用已确认的[山间棋亭效果图](pavilion-concept.png)，将远山、薄雾、木亭和竹叶作为统一背景。首页保留景色，操作页面叠加浅色面板，棋盘使用细木色边框。场上棋子继续使用原有汉字字体与准确的 9×10、15×15 网格。

## 对局与提示

- 电脑先检查自己能否立即连五；如果对手下一手可以连五，并且所有合法应对都无法阻止，电脑立即认输。判断涵盖落子、堵点、移动和吃掉连线棋子，不使用启发式分数或剩余棋子数量代替证明。
- 认输显示“电脑认输，你获胜”，不增加手数、不伪造落子记录，不播放上一手动画。存档保留结果，恢复时重放并验证认输局面；旧存档继续兼容。
- 准备页、玩法说明和棋盘操作区明确区分：先抽子可以看清种类后再选落点；直接点击空位，则落下后揭晓。抽出后仍必须放置，不能重抽或改为移动。

## 页面尺寸

- 菜单和准备页收紧标题、卡片与说明间距；短屏先收起装饰与棋盘缩略图，保留选择名称与尺寸。
- 操作按钮保留至少 44×44 像素的点击区域。普通短屏棋局保留较大的棋盘，出现防守提示时为提示留出空间。
- 横屏首页改为两列布局，继续棋局按钮出现后也能完整显示。
- 隐藏的读屏播报节点固定在页面原点，避免在页面底部额外撑出 1 像素。浏览器检查要求默认页面没有纵向溢出。
- 长规则、棋子说明及小屏主动展开的附加内容仍允许自然滚动。

## 验证与截图

[390×844 实际页面](pavilion-390x844.jpg) · [305×568 实际页面](pavilion-305x568.jpg) · [安全区模拟](pavilion-safe-area.jpg) · [浏览器记录](pavilion-report.json)

运行 `pnpm test` 检查规则、电脑、存档、房间及战术练习；运行 `node build.js` 生成静态制品。新增的 `pavilion-check.mjs` 使用标准 Playwright 包和独立静态服务，运行方法：

```sh
npm install --no-save --package-lock=false playwright
npx playwright install --with-deps chromium
node build.js
node pavilion-check.mjs
```

浏览器覆盖 305×568、375×650/651、390×700/701/740/780/844，另有 844×390 横屏和 1280×800 桌面。检查默认页、已有存档、可见好友入口、两阶段抽子、直接落子、刷新、认输结算和重新开局。安全区通过 CSS 模拟；这些记录来自 Chromium，不代表真机验证。

GitHub Actions 的 Mountain pavilion checks 保存完整截图与报告；仅开发用的 `codex/mountain-pavilion` 分支自动保存代表预览，`dev` 运行检查但不会由该工作流写回提交。
