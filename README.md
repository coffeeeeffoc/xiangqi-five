# 象五子棋

象棋的走法，五子棋的胜负。移动端优先，支持单人挑战、双人同屏、战术练习和好友房间，无第三方运行依赖。

## 移动端卡通改版（2026-10-05）

先完成[四页面效果图](docs/design/mobile-concept.png)，再按它实现奶油底色、珊瑚红 / 薄荷绿棋子、木棋盘和笑脸小伙伴。[设计说明](docs/design/mobile-design.md)记录页面与交互取舍。

首页只保留开始、续局、快速练习和两个小入口。开始后选择玩法，准备页设置难度与棋盘。游戏页专注棋盘，底部可直接抽子或选子移动；更多入口收纳规则、记录、棋池、设置与重开。说明、选题、提示、房间、重开确认与结算均切换页面，没有游戏弹窗。集成版好友 PK 同样使用独立页面，原临时房间收在“更多玩法”。

七种棋子都保留清晰的汉字并增加笑脸与小装饰。部署弹跳、移动按棋种使用不同轨迹、吃子飞出星光；动画期间输入锁定，系统减少动态效果时跳过动画。页面返回、刷新续局和浏览器返回不会取消已抽棋子；练习退出恢复原棋局。

## 本轮共享好友排位（2026-09-23）

在 small-games 集成构建中，“好友 PK · 全站榜”进入持久化共享服务；“休闲房”保留本项目原有临时房间。两者数据不会伪装互通。单机通过首页进入棋盘，更多选项使用独立页面并保留棋局；全屏收在对局小口袋中。

主榜固定 **9×10 自由部署**。红先黑后，服务端抽子并校验轮次、落点、吃子、连五与截止时间。胜 3、和 1、负 0，累计合法好友对战积分；每对身份每 UTC 日仅首场有效对局计分（北京时间 08:00 重置）。15 分钟或 600 手和棋；不足 10 手的超时/认输不计分，正常 9 手红方连五获胜可计分。旧休闲房、单机和机器人不计入全站榜；更改规则须更换 `xiangqi9x10-duel-v1` 版本。

从 **small-games 根目录** 构建 H5 与独立原生目标：

```powershell
pnpm --dir games/submodules/xiangqi-five build
node scripts/competition-build.mjs --game=xiangqi-five
node scripts/competition-build.mjs --native --game=xiangqi-five
```

微信输出 `apps/shell-minigame/dist/wechat/xiangqi-five/`，B站输出 `apps/shell-minigame/dist/bilibili/xiangqi-five/`。两者是真正 Canvas 棋盘与平台触摸入口，共享服务端身份/房间协议；当前缺本游戏 AppID、平台登录密钥及域名配置，构建标记 `preview-unverified`，尚未完成开发者工具或真机验收。配置与后端启动由根仓库共享部署文档维护，不把网页房间链接当作原生分享验证。

在本目录运行 `node --test competition.test.mjs`（需要 small-games 根服务规则），`node focus-check.mjs`，`node browser-check.mjs`。隔离 `competition_test` 后端启动后运行 `node online-check.mjs`，通过两个真实独立浏览器会话完成两局 PK、结算、排名和同对同日限分。`XIANGQI_COMPETITION_URL` 可指定当前联调入口；不要向生产数据环境运行此测试。证据和未验证项见 [RELEASE-REVIEW.md](./RELEASE-REVIEW.md)。

## 运行

安装 Node.js 22 或更高版本，无需安装依赖：

```powershell
npm start
```

打开 http://127.0.0.1:4173 。运行规则测试：`pnpm test`。

手机试玩：电脑和手机连接同一 Wi-Fi，在 PowerShell 用以下命令启动，然后在手机打开 `http://电脑局域网IP:4173`。如 Windows 弹出防火墙询问，仅允许需要的专用网络。

```powershell
$env:HOST='0.0.0.0'
npm start
```

## 六题入门，两手连招

首页“60 秒练一题”直接进入下一道未完成练习，也可在玩法选择页从“战术闯关”自由选题。前五题分别练习车的补线、马腿、象眼、炮架、兵可后退：都要用红方一步连成五枚。第六题练习防守，走一步消除黑方下一手的全部五连威胁；支持吃掉威胁与截断车路等多个正确解法。棋池已用完，不能再抽子，吃将本身不会判赢。

两道进阶题是真正的红—黑—红：第一题先填十字交点，黑方拆掉一条线后，红方用另一条线成五；第二题先用炮架吃将，再接线成五，也接受帅先吃将的替代计划。红方最多行棋两次，黑方从全部合法走法中选择让红方下一手胜着最少的应手，优先吃子；不会用固定答案放行或让黑方空过。当前回应会显示在第二手目标中，所有合法成五解法都算完成。练习刷新会重新摆题。

非法走法不消耗机会；达到行棋次数却未完成目标会给出原因并允许立即重试。独立完成获两颗星，使用提示获一颗星，可重练提升记录；选题页显示入门/连招完成数与 16 星目标，结算给出下一题目标和“邀朋友解这题”。练习进度使用独立本机存档，兼容原六题记录；原单人或同屏棋局与已抽出的棋子会保留，“返回棋局”恢复。练习不计入好友排位；在好友房间中不能进入练习。

“分享同题”与结算邀请优先使用系统分享，否则复制干净的网页链接；复制不可用时可手动选中复制。结算邀请按实际是否完成显示邀请文案，链接不含成绩。链接只含公开题目 ID，例如 `?challenge=cannon-link`，支持 GitHub Pages 子路径，不携带房间、服务地址、账号或凭证。八个合法 ID 为 `rook-bridge`、`horse-leg`、`elephant-eye`、`cannon-link`、`pawn-return`、`break-threat`、`crossroads`、`cannon-cross`；重复或未知 ID 不会装载局面。当前战术练习供 Web/H5 单机入口使用，原生排位 Canvas 入口尚不包含练习模式。

## 玩法（自由部署版）

- 可选 9×10 象棋棋盘或 15×15 五子棋棋盘。象棋棋盘显示楚河汉界，仅作标识、不影响走法；五子棋棋盘不显示。空盘红先黑后，各有车2、马2、相/象2、士2、帅/将1、炮2、兵/卒5。已有棋局切换尺寸时需确认重开。
- **部署：** 从剩余的实体棋子中等概率抽取一枚，必须放到任意空点。抽到后不能取消、重抽或改为移动；落子即换手。
- **快捷上场：** 未选中棋子时，可直接点击空位随机抽子并部署；也可先抽子查看。选中己方棋子后，点击目标位置仍按原规则移动。非法位置不会消耗棋池，同屏和联机使用同一规则。
- **胜负提示：** 获胜连线以金色连线和棋子光环标出，棋盘上方持续显示胜者与「再来一局」入口；同屏可直接重开，好友房间仍需双方同意。
- **移动：** 选择己方棋子，按其走法移动一次，可吃敌子。己方棋子不能互吃，被吃的棋子不回池。
- 车沿横竖直线走；马走日并检查马腿；象走田并检查象眼；士斜走一步；将帅横竖一步；炮不吃子时同车，吃子时须隔恰好一子。
- 取消九宫、象不过河、将帅照面、将军和将死；无飞将吃子。将帅被吃不直接判负。
- 兵卒可向前、向后、向左、向右走一步，没有方向或过河限制。
- 每次部署或移动后，任意种类己方棋子横竖斜连续 **至少五枚**，立即获胜。超过五枚也算。
- 棋池抽完仍能移动。轮到一方时无任何合法行动则和棋。没有自动重复局面判和，双方可协商重新开局。

点击己方棋子可查看合法落点，绿色点可走、红色虚线圈可吃。键盘 Tab 一次进入或离开棋盘，方向键在交叉点间移动，Enter / 空格选择；Home / End 移至当前行首尾，Ctrl + Home / End 移至整盘首尾，Esc 取消走子选择（不能取消已抽出的棋子）。落子动画或电脑思考后恢复原落点的焦点，可连续用键盘行棋；等待期间转到其他控件则保留新的焦点。说明页支持 Esc 或返回按钮回到上一页。

单人挑战由玩家执红先行，电脑执黑，双方遵守同一规则和随机棋池。可从对局“更多 → 调整玩法与难度”选择 **简易 / 标准 / 困难**，无需重开，刷新后保留难度；旧的入门/策略存档分别沿用简易/标准。

三个难度都会优先连五、阻止对手立即连五，并评估吃子与回吃，避免不断向车的攻击线上白送棋子。电脑使用三层算法：子力与连线及交换评估、带 Alpha-Beta 剪枝的对抗搜索、在搜索边界继续计算吃子和强制防守的静态搜索。部署按照剩余棋池中各棋种的真实数量计算期望值；已抽出的棋子按确定棋种计算，不偷看随机结果、不额外抽子。

| 难度 | 常规搜索上限（双方各走一次算两层） | 吃子延伸上限 | 每步搜索时间预算 |
| ---- | ---------------------------------- | ------------ | ---------------- |
| 简易 | 2 层                               | 2 层         | 约 0.25 秒       |
| 标准 | 3 层                               | 3 层         | 约 0.9 秒        |
| 困难 | 5 层                               | 4 层         | 约 4 秒          |

搜索采用迭代加深，到预算时使用上一轮完整结果，实际深度取决于局面、随机分支和设备性能。为控制移动端耗时，普通候选有宽度限制，并缓存已算出的局面；立即获胜及强制防守在限制候选之前检查全部合法行动。基础候选评估和线程启动会产生少量额外耗时，以上不是硬实时承诺。困难会计算更多后续攻防，但不是穷尽所有走法的完美棋手。

电脑在独立 Web Worker 内计算，思考时锁定玩家输入，重开或切换对局模式会取消旧计算。金圈提示对方下一手可成五的位置，选中棋子会显示该棋子的走法。两种棋盘均可单人或同屏游玩，切换模式需要确认重开。

本机棋局每次行动后自动保存，包括抽出尚未部署的棋子；刷新重放原规则恢复，不会重抽。损坏或非法的存档不会进入游戏。浏览器禁用存储时页面会明确提示。当前只保留最近一局，不含账号或跨设备同步。

## 多端交互

竖屏以棋盘为中心，回合与必要操作紧贴棋盘，抽子和移动放在拇指易触及的底部。手机横屏将棋盘放右侧，轻量状态与操作放左侧；桌面沿用简洁的手机页面结构。玩法、棋池和全部记录按需进入独立页面，离开棋盘不会重开或清空棋局。

棋盘支持双指缩放和平移（100%–300%）；棋盘旁小放大镜可单指放大，“恢复”归位。双指手势与取消不会落子；15×15 棋盘需要更大落点时可放大后操作。全屏收在“更多”中；不支持或浏览器拒绝时准确提示，仍可继续游戏。横竖屏变化只恢复缩放。

首页使用双棋子插画，场上棋子使用本地宋体字形子集与随棋格缩放的字号，可独立静态部署。抽取后显示具体棋种与放置提示；菜单、说明、练习及结算采用统一的轻描边样式。动画具有超时清理，不会因浏览器取消动画而永久锁定输入。设计图、实际截图和验证见 [全页面样式优化](docs/design/mobile-refresh.md)；Android/iOS 真机验证尚未完成。

## 好友房间

点击“好友房间”创建或加入两人房间：创建者红方，加入者黑方。目前是 1v1 邀请房间，没有 2v2 共享棋池或自动匹配。邀请码/链接不含玩家凭证。同一 Wi-Fi 试玩时，用电脑局域网地址打开页面再创建房间，生成的链接才能被另一台设备访问。

服务端统一抽子、校验回合和判胜；客户端提交意图及棋局版本，约每秒同步一次。重复或过期操作会被拒绝并显示原因。断网锁定行动并重试同步；重开需双方同意，任何一方可取消申请。

单人和同屏棋局自动保存在 localStorage；进入房间前保留本机棋局，离开后恢复。联机凭证保存在当前标签页 sessionStorage，刷新可恢复原席位。返回本机棋局会放弃席位，原房间码不能再次取回已占用席位，可另建房间。

房间为单进程内存状态，最多 100 个，闲置一小时或创建满一天后过期，服务重启清空。适合朋友试玩，未加入持久化、多实例共享、账号或平台 SDK。

## GitHub Pages

**GitHub Pages 能托管静态前端，不能运行房间 API 或充当实时消息中转。** 执行 `pnpm build` 后将 `dist/` 作为静态发布内容；相对资源路径支持仓库子路径。静态包包含电脑 Worker，单人和同屏游玩无需后端。

好友联机还需一个支持 Node 的服务运行 `npm start`，以 HTTPS 提供房间接口。配置 `HOST=0.0.0.0`、平台分配的 `PORT`；前后端分离时，将 `FRONTEND_ORIGIN` 设为 Pages 的精确来源，例如 `https://用户名.github.io`（不含仓库路径）。发布入口可用 `?server=https://后端域名` 指定服务，邀请链接自动携带；开发者也可展开“自建房间设置”指定地址。同源提供网页和 API 时无需设置 CORS。界面会先检查 `/api/rooms/health`；无服务的静态版本明确提示尚未开放在线房间，并提供同屏入口，不会让玩家反复创建失败。

在线试玩：https://coffeeeeffoc.github.io/xiangqi-five/ 。源码：https://github.com/coffeeeeffoc/xiangqi-five 。WebRTC 可以直连，但信令交换和部分网络所需的 TURN 中继仍要解决。

参考：[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)、[WebRTC 建连说明](https://webrtc.org/getting-started/peer-connections?hl=en)。

## 验证

`pnpm test` 使用 Node 内置测试，覆盖两种棋盘、所有走法、抽子锁定、吃子判胜及真实 HTTP 房间的身份校验、版本冲突、双人重开。`computer.test.js` 另外覆盖三档避免连续送车、受攻击位置立即连五、吃掉连线棋子防守、炮架被吃后的交换陷阱、棋池概率与抽子锁定、超时回退及存档兼容；困难档的连续取胜布局用独立递归检查枚举对手全部合法应对，不依赖搜索评分判定通过。

`pnpm build` 生成静态前端，再运行 `node mobile-pages-check.mjs` 验证本轮移动端页面。脚本使用实际触屏输入，覆盖 305×568、390×844 手机竖屏与 844×390 横屏、两种棋盘完整显示、44 px 核心触控按钮、首页/玩法选择/设置/游戏/小工具/规则/棋子说明/记录/棋池/练习/提示/房间/重开/结算页面，以及待落棋子、存档、刷新续局与取消重开。双指缩放取消不会落子，改棋盘须经过独立确认页；详细规则默认收起。

浏览器检查还验证普通动效与减少动效设置、连续键盘行棋和焦点恢复、真实电脑 Worker 在玩家查看规则时完成回合而不抢焦点、练习提示/解题/一星记录与原棋局保护。两个独立浏览器通过真实 HTTP 房间创建、邀请、加入、触屏轮流落子与同步，离开后恢复原本机棋局；共享开发者模式的显式开启/关闭也保留。截图和检查记录输出到 `.turbo/mobile-pages/`。脚本优先使用已安装的 Playwright，可通过 `XIANGQI_PLAYWRIGHT_MODULE` 指定其模块路径、`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定 Chromium。本轮验证环境为 Linux Chromium 151 的移动触屏仿真；尚未完成真实手机或跨运营商网络验证。

`challenges.test.js` 枚举每题全部合法红方走法，并枚举防守题每个黑方应对；两手题额外穷举每个红方首着、每个合法黑应手与所有红方第二着，用真实五连独立证明强制解与多解。

## pnpm 与 small-games 集成

使用 Node.js 24.21.0 与 pnpm 12.6.0。独立克隆后执行 `pnpm install --frozen-lockfile`、`pnpm dev`、`pnpm test`、`pnpm build`。静态产物位于 `dist/`，可部署到任意静态服务器。

本仓库同时作为 [small-games](https://github.com/coffeeeeffoc/small-games) 的 `games/xiangqi-five` Git submodule。在父仓库运行 `pnpm --filter @coffeeeeffoc/xiangqi-five dev` 可独立开发；父仓库的 Web Shell 构建会包含静态产物。内部技术栈及游戏逻辑保持独立。

`pnpm-lock.yaml` 用于本仓库的独立安装；父仓库根锁文件用于 workspace 安装。依赖变更后需分别更新两份锁文件。先提交并推送本仓库，再在父仓库提交 submodule 的版本指针。

推送到 `main` 自动执行测试、构建并部署到 [GitHub Pages](https://coffeeeeffoc.github.io/xiangqi-five/)，也支持 Actions 手动触发。其他分支和 PR 自动测试、构建，不覆盖线上站点。仓库 Pages 的 Source 使用 **GitHub Actions**。
